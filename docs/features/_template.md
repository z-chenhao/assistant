# 功能名称

用一两句话解释用户问题和目标结果。

[主索引](../feature-map.md) · [技术方案模板](../designs/_template.md) · [测试方案模板](../test-plans/_template.md)

## 功能说明

说明谁在什么场景使用、完成后得到什么。列出依赖、支持平台和不在本轮范围内的行为。

## 需求与验收

为每项需求使用主索引分配的稳定 ID，并添加同名小写 HTML 锚点。主索引的链接定位到这里，不复制维护另一份完成状态。

每项写清：

- 需求：用户可观察的行为。
- 当前实现：真实入口、调用链及已知限制。
- 边界与剩余工作：缺失链路、配置前提和未验证项分别描述。
- 验收目标：正常、失败与必要恢复行为。

## 如何使用

给出已实现入口、前提和真实操作。尚未实现时明确说明，并把未来用法标为目标，避免把设计写成教程。

## 关联文档

新功能应链接同名技术方案和测试方案，详细命令可以引用已有 guide。操作示例不包含真实凭据。

## 维护

需求变化先更新本文，再同步主索引、技术方案与测试方案。合并多个需求时保留既有 ID 的去向；不复用历史 ID。
