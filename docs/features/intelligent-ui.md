# 受控富 UI 交付

把语义结果呈现为文本、表格、附件、进度和确认组件。

[需求主索引](../feature-map.md) · [技术方案](../designs/intelligent-ui.md) · [测试方案](../test-plans/intelligent-ui.md)

## 功能说明

正常回复能产生适当的受控组件，失败可退回语义文本。

本文描述用户行为和范围；逐项完成状态以主索引为准。当前能力依据代码静态盘点，配置可用性与真实服务/模型质量需分别验证。

## 需求与验收

<a id="f-021"></a>

### F-021 · 富组件从生成到交互的闭环

**需求**：正常回复能产生适当的受控组件，失败可退回语义文本。

**当前实现**：Main 可在普通最终回复中给出渠道无关的 `steward-result` 结构化数据，Delivery Composer 将其映射为受控表格、进度摘要和问答表单，保留完整文字替代内容。Web 的表单回答通过原消息接纳路径进入 Main；并发重试只保存一次，重启或刷新后显示已接受的回答。普通文本、附件和冻结审批卡继续走现有路径。

**边界**：v1 表单只收集必填文本字段，不执行模型提供的 URL、代码或外部动作。回答不批准工具，也不直接重启 Task。进度组件表达回复中的事实摘要，不替代 Host 的 Task 状态或通知规则。Web 支持交互表单和无 JavaScript 提交；飞书受控卡片与 TUI 保留可读内容，用户仍可用普通消息回答。组件选择和内容的真实模型质量另行验证。

**验收目标**：经真实 Main/Bridge/Delivery 链路生成表格、进度与表单；确认仍使用 Host 冻结审批；未知版本、组件或坏数据降级为文字；表单校验、断网、刷新、并发重试、进程重启和来源绑定保持回答与草稿正确。

## 如何使用

可请求 Ghost「按价格和适用场景比较这几个方案」或「先收集目的地和出发日期」。适合时，回复会显示表格、摘要或问答表单；简单回答仍可使用普通文字。无需安装前端服务。

填写表单后选择 **Send response / 发送回答**。所有字段均为必填文本，每项最多 4096 个 UTF-8 字节，整份回答（含问题和字段名称）最多 16 KiB。回答作为普通用户消息交给 Ghost；页面更新保留其他表单与对话输入框的草稿。无法确认发送时保留填写内容，先检查对话再重试；同一份已提交表单不能覆盖原回答，需要更正时发送一条普通消息。

刷新或重启后，已保存的表单显示原回答并停止重复提交。关闭 JavaScript 仍可填写和提交；失败页面保留可复制的回答草稿。旧只读表单保持展示用途，未知或不受支持的内容显示文字替代。待审批动作继续显示独立确认卡片，表单不提供审批入口。
