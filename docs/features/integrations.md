# MCP 与真实外部能力

将配置的外部工具纳入同一权限、审批和恢复体系。

[需求主索引](../feature-map.md) · [技术方案](../designs/integrations.md) · [测试方案](../test-plans/integrations.md)

## 功能说明

操作员可把允许的本地 stdio 工具加入 Agent 工作面。

用户能连接实际数据源与服务，支撑研究、日程、监控等具体工作。

本文描述用户行为和范围；逐项完成状态以主索引为准。当前能力依据代码静态盘点，配置可用性与真实服务/模型质量需分别验证。

## 需求与验收

<a id="f-024"></a>

### F-024 · 受限本地 MCP 工具接入

**需求**：操作员可把允许的本地 stdio 工具加入 Agent 工作面。

**当前实现**：启动服务器、tools/list、tools/call、schema 指纹与工具允许列表已实现。统一经 Code Mode 调用，不提供 exposure 或单工具模式；脚本渐进发现，500 工具目录不预载全部 Schema。Main 和 Worker 均按自己的冻结权限执行。

**边界与剩余工作**：当前子进程受限、无继承凭据/网络；这不是通用远程认证 MCP 客户端。

**验收目标**：真实协议验证发现/调用、漂移拒绝、取消回收与外部效果审批。

<a id="f-025"></a>

### F-025 · 可认证的真实服务接入

**需求**：用户能连接实际数据源与服务，支撑研究、日程、监控等具体工作。

**当前实现**：已有本地 MCP 与配置型 Guest 浏览器基础；GitHub 精确 PR 监听可从 SecretStore 解析 PAT，经 `/user` 验证身份后读取评审及当前提交的 CI。凭据失效、来源失效、限流与协议错误通过安全状态码诊断；替换同一 SecretStore 引用中的 PAT 后下轮重试，无需将密钥复制到状态库。

**边界与剩余工作**：此接入只读 GitHub.com 的一个明确 PR，不提供 Agent 服务工具、远程 OAuth MCP、自动签发/刷新 PAT 或授权写动作；统一连接与其他服务仍待实现。真实账户权限、PAT 到期恢复及实际平台结果需 Live 验证。

**验收目标**：在明确服务上完成真实读取/授权动作/失效恢复；无凭据泄漏，审批及 unknown 语义保持一致。

<a id="f-042"></a>

### F-042 · 可靠的环境事件监听

**依赖**：F-025 服务接入与 F-020 渠道。完成状态以主索引为准。

**需求**：用户授权监听实际工作来源后，外部评审、CI 等变化能可靠进入助手，断连恢复后仍能追溯接收与处理情况。

**当前实现**：显式配置一个 GitHub.com 仓库/PR 后，前台 Web/TUI/Automation 运行时持续读取 review comments、已提交 reviews 与当前 PR head 的已完成 check-runs。完整分页扫描后，将来源版本身份、观察内容、健康及补读成功时间原子保存到 `state.db`，通过 `github status/events` 查看；重复和乱序不重复保存同一来源版本，自身份的评论/评审不回流。

**边界与剩余工作**：未绑定的观察只供本机诊断；本机所有者可将当前精确 PR 显式关联到已有 Task，只有绑定后新观察才交 Main 作为不可信外部证据，再由 Main 判断是否在原目标内追加工作。事件不能创建新 Task 或扩大权限；移除/切换配置与明确撤权持久停止旧绑定，暂时轮询故障保留已接纳观察；GitHub 因果 Main/Task 结果复用 F-020 回原渠道/话题，显式通知偏好仍优先。补读重扫 GitHub 仍保留的当前资源；不保证已删除评论、扫描间消失的中间修改、旧 head 的 CI 或普通 issue comments/legacy commit statuses。每类至多扫描 20 页、每页 100 项；总规范化内容至多 8 MiB，超过界限显示 `HISTORY_LIMIT` 并保留原成功边界，不能称为完整审计流。

**验收目标**：重复接收不重复接单；断连、重启、乱序和来源权限撤销后按明确边界恢复或停止；监听中断不展示为正常。接收信息不授予任务执行或外部动作权限。

## 如何使用

F-069 已提供搜索与公开网页读取入口，F-067 提供其显式可选后备；其余新增 connector 与相关候选尚无可用入口。分类见[术语与登记边界](#术语与登记边界)。F-069 的配置及限制见下方独立条目；以下 MCP 与 GitHub 监听用法只适用于 F-024/F-025/F-042。接入顺序见[个人 Connector 优先级](../feature-map.md#personal-connector-priorities)。

当前在配置中指定本地 MCP 可执行文件、独立目录和允许的工具及权限。启动时纳入冻结注册表，Agent 通过同一工具发现和执行入口使用。

GitHub 监听使用以下显式配置；不要把 PAT 字面量写入 YAML。PAT 需要所选仓库的 Pull requests 和 Checks 读取权限，并能通过 `/user` 返回当前用户身份；SecretStore 支持操作系统凭据引用或显式环境引用。配置示例同 [config.example.yaml](../../config.example.yaml)。

```yaml
github:
  repository: owner/repository
  pull_number: 123
  credential_ref: env:STEWARD_GITHUB_TOKEN
  poll_seconds: 60
```

启动既有 `web serve`、TUI 或 `automation work` 的生产运行时即持续监听；不要求模型已就绪。`poll_seconds` 默认 60 秒，允许 5–3600 秒。配置变更在重启后生效；移除配置即不启动监听，当前命令不再展示旧范围为活动来源。仅配置 SecretStore 引用，不会自动选择模型。

```sh
steward -config /absolute/config.yaml github status
steward -config /absolute/config.yaml github poll
steward -config /absolute/config.yaml github events
steward -config /absolute/config.yaml github events 101
steward -config /absolute/config.yaml github stop
steward -config /absolute/config.yaml github resume
```

`poll` 执行一次真实只读扫描并返回状态；失败返回非零，同时保留安全诊断。`events` 按 sequence 倒序最多 100 项，下一页传本页最小 sequence；正文最长 16 KiB，截断时明确提示沿来源 URL 读取全文。`status` 区分 `never_checked/checking/healthy/interrupted/stale/stopped/privacy_stopped/not_configured`；超过两倍轮询间隔的旧成功/进行中扫描显示 `stale`，不冒充仍正常监听。CLI 控制可在模型或执行依赖不可用时使用。

`stop` 持久停止并 fencing 在途扫描，普通 `poll` 和重启不能恢复。Forget 同样停止原授权 epoch 的接收，并隐藏旧 epoch 观察；明确 `resume` 才更新接收意图。历史相同 event_key 不会因 resume 重新入库或暴露，只有此后尚未保存的来源版本进入当前观察。它不恢复 Task 或外部副作用。仓库名称对应的不可变 repository ID 改变时 fail closed，不把新仓库当原来源。

### 将 PR 后续反馈关联到已有任务

先配置/成功 `github poll`，确认确切仓库及 PR；再由本机所有者选择已存在、当前隐私作用域内的 Task。`task_epoch` 是所选 Task 当前执行代次，`version` 是 `github binding` 返回的关联版本（首次为 0）。关联只允许 active 或自然完成的 once Task；暂停、取消和用户显式 complete 的当前代次不能绑定。

```sh
steward -config /absolute/config.yaml github binding
steward -config /absolute/config.yaml github bind <<'JSON'
{"task_ref":"task:opaque-ref","task_epoch":1,"version":0}
JSON
```

绑定不回放已经收下的历史观察。上述旧格式绑定明确启用所有新观察。可先按一种事件类型观察匹配结果，再显式启用规则内的自动接续，见 [F-045 规则用法](automation.md#f-045)。接纳的新版本经现有单 Main/Actor 读取 JSON 证据框，判断是否需要 `task_manage append` 继续同一 Task。同一观察只接受一次不同的追加动作；相同来源与相同参数重复请求复用原回执。歧义、超范围、未知副作用或不需继续时，Main 应解释/询问用户，不建立新工作或猜测外部授权。source Main 可读已有授权数据和保存本地产物，不能直接发外部动作、创建 Automation 或写长期 Memory；真正工作交既有 Task Worker 和审批管线。

```sh
steward -config /absolute/config.yaml github unbind <<'JSON'
{"version":2}
JSON
```

使用实际 `github binding` 版本，不固定复用示例值。unbind、监听 stop、Task pause/cancel、用户显式 complete、Forget 和来源撤权会使待处理/正在推理的旧因果失效；恢复监听或普通重启不重新授权已停止的绑定。新用户输入优先建立自身的 Main，保留不可变接收回执，不被旧观察吞并。once Root 自然结束并非人工停止，原绑定可接续；人工 complete 则需要用户明确 append 进入新代次后再重新绑定。未知效果不会因为收到评审而重试。

远程 OAuth MCP、邮件/日历等不能当成现成产品开关。真实账户权限及 GitHub 保留历史的补读范围仍需独立验证。

## 个人 Connector 需求

本节按明确的外部应用／服务登记 connector，每项拥有主索引中的独立 ID，不把一个平台的完成扩展到另一个平台。当前用户是希望延续个人研究、工程交付及生活安排的本机所有者。委托过某项工作只证明场景需求，不能直接推出需要某个 connector。

### 术语与登记边界

本规划中的 **connector 是面向明确外部系统的集成适配器**：将该系统的数据／资源和允许的业务操作接入 Agent，并处理适用的认证、权限、错误及连接生命周期。按外部系统划分 connector，按具体操作划分 tool；只读系统和公共数据服务也可以有 connector，不要求每项都有 OAuth、写操作或后台同步。

| 层次 | 示例 | 在本规划中的归属 |
| --- | --- | --- |
| 外部系统 connector | Gmail、GitHub、高德、飞书云文档、Jellyfin | 本节登记与排序；一个 connector 可暴露多个工具 |
| 工具／执行通道 | 浏览器操作、文件读取、SSH 命令执行 | Agent 执行能力，不因可操作外部系统就各算一个业务 connector |
| 模型能力／供应商 | 图片生成、视觉理解、语音识别 | 模型能力接入；“图片生成”本身不是一个外部业务系统 |
| 数据导入 | 聊天导出、会话 JSONL、健康 XML | 一次性迁移或文件读取，不等于连接了来源应用的账户／业务接口 |
| 协议 | MCP | 可承载工具和资源的协议，不等于某个 connector，也不限定其业务边界 |

例如 Gmail connector 可提供查邮件、读线程、保存草稿和发送工具；高德 connector 可提供地点、路线和天气工具。二者的业务边界由所连接系统和实际授权决定。MCP 的工具／资源划分见[官方服务端概念](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/learn/server-concepts.mdx)，不把一个 MCP server 或一个 tool 机械等同于一个业务 connector。

F-048–F-054 保留原 ID，但归为[相关能力候选](#相关能力候选非-connector)，不计入 connector 数量或顺序，也不因需求分析自动成为已确认开发任务。F-057 只有连接 HealthKit 的设备端集成可作为 connector 候选，XML 导入仅是文件能力。Tavily 是公共检索服务 connector，与连接用户个人业务资料的 Gmail 等应区分用途；不能仅从“经常查资料”推断必须采用 Tavily。

F-069 Web Access Connector 是用户统一使用的搜索／网页访问接入，内部组合已允许的服务适配器和正文读取能力；它不是一个新的外部系统，不与 F-046/F-067/F-068 重复计算供应商数量。服务条目独立维护兼容性，组合能力负责选择链路及统一交付。

### 选择依据与证据边界

需求依据为经用户授权查看的 ChatGPT/Codex 聊天目录及部分近期消息，以及仓库当前能力；属于定性抽样，不是完整历史或使用频次统计。对话里的旧执行结果只用于识别委托意愿，不证明当前设备、账户或服务仍处于相同状态。只保留下列抽象任务模式，不保存私聊原文、私有聊天链接、身份资料、健康数值、账户信息或设备地址。

个人 connector 排序以 ChatGPT 日常问题为主要证据：公开资料查找与核验，餐厅／车站／路线／天气等现实情境解释，个人资料找回，生活数据回顾，以及工作材料整理。Codex 的代码交付与设备维护保留为独立工程需求，不因工程调用多就占据个人业务 connector 的首位。

排序先看已明确且反复委托的任务，再看接入后是否能补足当前缺少的事实、减少手工截图／粘贴，以及现有搜索或浏览器能否覆盖；同时考虑实际接口、授权和维护成本。不按聊天条数机械计分，一次旅行内的连续追问不能直接视为全年频次。健康数据、邮件或工作材料的需求，不自动证明资料分别在 Apple Health、Gmail 或飞书；未确认来源的项目只列需求优先级，不能直接进入实施队列。

| 已观察的任务模式 | 所需接入或能力 | 判断边界 |
| --- | --- | --- |
| 找原文、核查帖子、比较软件和设备、阅读技术方案 | 搜索、网页正文、来源与时间可核查 | 已看到明确委托；不预设所有网站都可抓取 |
| 改代码、开 PR、审查、跟进 CI 并修复 | GitHub 账户资源与授权协作动作 | 明确且重复；已有精确 PR 监听只覆盖其中一部分 |
| 检查本机、清理资源、维护家庭设备及远端服务 | 本机、SSH、受控浏览器接入 | 明确且重复；操作历史不构成未来修改授权 |
| 追问旧对话、旧图片和另一 agent 的上下文 | ChatGPT、Codex、Pi 的独立来源接入 | 需求明确；历史答案不直接晋升为事实或指令 |
| 图片生成／修改、角色与品牌设计、动画需求 | 图片服务，保留素材和版本关联 | 明确；静态图片和实际动画分别验收 |
| 海外地点链接、餐厅与车站、路线和票据解释；国内天气／出行 | Google Maps、高德，以及邮件／浏览器的互补 | 地点任务明确；不能由此认定已授权定位、下单或付款 |
| 生活记录、睡眠回顾、文档整理和提醒 | 健康数据、文档、日历的候选接入 | 数据需求明确；Apple Health、云盘及具体日历账户未全部确认 |

本机操作、历史导入和图片生成的需求用于规划相应能力，不计为业务 connector；翻译、写作、一般推理及 Steward 内部 Memory/Task 也不另造 connector。浏览器书签或已打开页面只表明服务可能相关，不能作为 Gmail、云盘或视频处理频率的证明。飞书个人收发继续由 [F-020](channels.md#f-020) 维护；它是已有消息集成，拥有机器人身份不代表已经能读取用户的云文档、日历或全部聊天。

### F-046 · Tavily 搜索与网页正文

**需求与依据**：用户交给助手原文查找、技术调研、帖子核验和商品比较后，能得到带来源的可核查结论。需求明确且重复出现；本项保留为 Tavily 的独立接入，免费优先的 Exa MCP／SearXNG 候选分别见 F-067/F-068，不再将 Tavily 预定为唯一或首个默认服务。

**当前实现**：F-069 已有自建 Search API 适配器及协议回归；独立 Extract 正文操作和真实账户 Live 待完成。

**目标与边界**：首版支持搜索及指定公开 URL 正文提取，保留来源 URL、读取时间、可用的发布时间、截断与提取失败。区分原文、转载和搜索摘要；不自动登录受限站点，不将私有资料拼入公共查询。认证与用量走 SecretStore 及现有额度机制。[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) 与 [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract) 是不同操作，搜索命中不表示正文已读。

**验收目标**：找到指定原文并读取后引用；无结果、过时内容、正文不可达、限流、取消与正文中的恶意指令均有真实边界，不能把摘要当成全文或将第三方内容当成授权。

<a id="f-047"></a>

### F-047 · GitHub Connector

**需求与依据**：用户希望围绕明确仓库完成查 issue/PR、读取 diff/CI、准备及发布评审或 PR、在授权下完成合并。工程交付和 CI 跟进有明确重复委托。

**当前实现**：F-025/F-042 已提供一个精确 PR 的只读 PAT 监听；尚无上述账户资源及协作工具入口。本项新增工具闭环未实现，不能用已有监听认定其部分接通。

**目标与边界**：先接明确仓库的读取和 PR/CI 证据，再接授权写动作；身份、仓库、head 和具体参数必须明确。采用 [GitHub 官方 API](https://docs.github.com/en/rest/pulls/pulls)；PAT、GitHub App 等认证方式在实现时按实际部署选择，不预先稳定通用账户协议。F-026 持有代码修改集／远端交付关系，F-042 持有事件监听，F-045 持有主动接续；本项持有 GitHub 服务操作，避免建立第二套监听或任务系统。发布、合并和分支删除仍服从既有审批与治理。

**验收目标**：读取精确 PR 并解释对应 head 的 CI；经明确授权创建草稿 PR／评论并核实回执；head 变化拒绝旧合并请求，权限不足、撤权、限流和未知写结果不能扩大范围或重复发布。

<a id="f-055"></a>

### F-055 · Google Maps Connector

**需求与依据**：用户在海外出行中实际交给助手 Google Maps 地点链接、餐厅与车站问题，并要求解释路线及目的地；有直接证据。

**当前实现**：未接通 Google Maps Platform。

**目标与边界**：首版接地点解析、地点详情及步行／公共交通路线，支持用户给定的地点和起终点。[Places](https://developers.google.com/maps/documentation/places/web-service/overview) 与 [Routes](https://developers.google.com/maps/documentation/routes/overview) 分别提供地点与路线能力，需要核实计费、区域和结果使用限制。地图上有地点不代表找到正确车站入口；评论、营业信息和菜单必须区分，不能凭评论编造特色菜。公开地图 API 不等于用户收藏／时间轴访问。

**验收目标**：解析地点链接后核对地点身份、城市及入口／路线；时区、营业时间、无路线、短链失效、来源过时和同名地点不误导。导航链接不表示已订票或预约。

### F-056 · 高德地图 Connector

### F-069 · Web Access Connector

**需求与消费者**：Main／Task Worker 用同一 Registry／Code Mode／Executor 完成公开研究、网页读取和证据续读。connector、选路、服务协议、工具契约及状态管理均由 Steward 自建，不安装外部 agent SDK、不复制插件实现或类型，也不接管其他助手的会话与凭据。

**入口与行为**：`builtin__web_search` 支持单查询或最多八个查询、显式 provider、域名条件、时间偏好、来源正文及摘要工作流。`builtin__fetch_content` 支持最多八个公开 HTTP(S) URL 的 readable／raw／answer 模式：本地提取 HTML Markdown、文本、PDF 和图片；问答使用当前冻结模型，并保存原始提取证据。`builtin__get_search_content` 从返回的 `responseId` 续读或 exact／case-insensitive／fuzzy 查找；分页和片段坐标是 UTF-8 字节偏移，不拆分字符，fuzzy 按顺序匹配忽略空白的词组。`builtin__source_check` 收集来源、原文片段及哈希供人工判断；有来源为 `unclear`，无证据为 `missing-evidence`，不声称自动裁定支持或反驳。旧 `builtin__web_fetch` 继续提供原有公开 HTML／文本读取。

**选路与配置**：默认按已配置 SearXNG → 当前账户原生搜索 → 显式启用的 Exa → 已配置 Tavily 顺序尝试。零命中成功即停止；认证拒绝、预算阻断、无效响应和取消不换源。临时不可用、限流和明确不支持可进入下一来源。显式 provider 不换源，也不能绕过冻结的 `source_order` 目的地限制；不并发广播或自动部署／选择公共实例。

```yaml
web_access:
  source_order: [native, exa]
```

只使用账户原生搜索可设 `source_order: [native]`。默认不启用 Exa；兼容配置 `exa_fallback: true` 时将其加入默认顺序。自托管服务设 `searxng_url: https://search.example`，可选 `searxng_secret_ref` 指向 SecretStore 的 Bearer 凭据。Tavily 使用 `tavily_secret_ref`，例如显式 `env:TAVILY_API_KEY` 环境引用；密钥只从 SecretStore 解析，不写进配置或继承给正文提取进程。SearXNG 使用[官方 JSON Search API](https://docs.searxng.org/dev/search_api.html)，Tavily 使用[官方 Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)。改变来源、凭据引用、解析程序或锁定依赖会改变冻结工具身份，旧 Run 不静默套用新配置。

**账户与费用**：当前模型为 Steward `openai_account` 时使用自身 Sign in with ChatGPT 的 `api.openai.com/v1/responses` 托管搜索，要求实际完成的搜索事件；端点地址不意味着 API Key 计费。批量原生查询、网页问答及摘要各自经独立交换、预算、用量和撤权 fence，保留主模型快照。只发送本次查询或明确请求处理的证据，不发送聊天历史、附件或工具目录。当前账户路径已有真实账户／Main／Code Mode 搜索验收；其他账户、模型与订阅政策仍按实际能力验证。外部搜索费、服务额度与 token 用量分开，不宣称已知总费用或无限免费。

**过滤保证**：原生搜索将包含域名传给 hosted tool；排除域名和返回来源列表由本地严格筛选，带域名条件时不把未筛选的供应商回答当成结果。SearXNG 的时间范围依赖实例／引擎，Tavily 的时间范围由服务处理；日期没有统一硬保证。Exa 当前窄 MCP 工具不能承诺高级过滤，带域名／日期条件时明确不支持，不把条件降级为查询文字却声称成功。

**提取与持久化**：网络访问在 Go Host 校验并固定公开 DNS，重定向重新检查，拒绝内网／保留地址、非标准端口及任意本机路径；不带浏览器登录或账户认证。提取进程只收到本次有界文档，使用独立 HOME／TMPDIR、不继承密钥且禁用解析器网络请求。HTML 通过通用 Readability／Defuddle／Turndown 解析，PDF 通过 unpdf 本地提取；未配置解析程序时 HTML 可用基本正文提取，PDF 明确不可用。标准安装自动装配 `web-extract.mjs`；显式安装可指定绝对路径 `extract_command`／`extract_script`。下载至多 8 MiB，PDF 至多 200 页，文本至多 5 MiB，证据集至多 24 MiB；超限明确失败。图片限 32M 像素并转为最大 2000×2000 JPEG；至多八个媒体附件，与状态和工具终态原子提交。

全文、来源、时间与证据片段保存在当前作用域 Artifact，`responseId` 就是该 Artifact 引用，不依赖进程缓存。问答不会覆盖原文；摘要 `summary-review` 返回 `reviewRequired` 的未批准草稿。查找只读已保存证据；已完成工具结果重放不重新访问网络，未知的搜索／提取不自动重复计费。所有内容均为不可信证据，不能授予权限；可见性、Forget、发布和取消继续由既有机制负责。

**明确缺口**：未实现独立 OpenAI API Key／私有订阅端点、其他搜索供应商、Tavily Extract、登录网页／浏览器升级、GitHub clone、YouTube／本机视频或交互摘要编辑器。GitHub 服务闭环仍归 F-047；普通公开网页可尝试本地提取，不能称为已读取完整仓库。免费服务限流、中文质量、SearXNG 真实实例和 Tavily 真实账户分别验收，F-069 仍登记为部分完成。本机 fake-IP 将公网 DNS 改为保留地址时会安全拒绝，没有为代理关闭保护。

## 相关能力候选（非 Connector）

F-048–F-054 分别属于执行能力、历史资料导入或模型能力，保留 ID 以便追溯，但不进入 connector 排序。这些需求方向尚待另行确认，以下范围与验收仅为候选，不构成当前 connector 接入任务。

<a id="f-048"></a>

### F-048 · macOS 本机文件与运行状态

**需求与依据**：用户希望助手检查开发环境、目录占用、后台服务及配置，并准备可审查的维护动作。本机维护委托明确且重复。

**当前实现**：已有显式代码仓库、Artifact 和 Steward 自身运维能力；没有面向任意已授权本机资料／服务的 connector。F-027 的隔离 Guest 不等于用户宿主机。

**目标与边界**：首版限定为用户选择的目录、具名服务和只读诊断；在此基础上才提供具体维护计划与授权修改。F-012 管理导入后的 Artifact，F-026 管理仓库工作副本，F-028 管理 Steward 自身健康。不得把整个 HOME、系统凭据库、浏览器 profile 或任意提权 shell 作为默认能力。

**验收目标**：选定目录后能解释占用和读取确切配置；符号链接、越界路径和不必要的敏感文件读取被拒绝；维护动作能预览目标、核对变化并在未知结果时停止盲重试。读取诊断不宣称已修复。

<a id="f-049"></a>

### F-049 · SSH 远端设备与服务

**需求与依据**：用户希望检查和维护已拥有的远端服务器、家庭设备与网络服务，比较方案时验证真实运行状态；明确且重复。

**当前实现**：现有 SSH 仅用于显式 macOS Guest，尚无通用远端设备操作入口。

**目标与边界**：逐台绑定主机身份、账户、host key、凭据引用与允许的读取／动作范围。首版只读服务、日志与资源状态，之后才接具名维护动作；不遍历用户 SSH 配置／agent，不借 Guest 连接扩大到其他设备。影响网络的修改需有具体回滚安排，但回滚失败或断连不自动表示远端动作没执行。

**验收目标**：连接受控主机并返回带来源和观测时间的诊断；host key 改变、账户撤销、超时与取消正确处理；维护前后的真实状态可核对，断连后的未知效果不通过重新执行消除。

<a id="f-050"></a>

### F-050 · 用户选择的 Chrome 页面与会话

**需求与依据**：用户会让助手查看当前打开的页面、解释账户控制台、辅助网页操作；需要连续使用已经展示的上下文，减少手工截图和复制。

**当前实现**：F-027 提供配置型 Guest 浏览器，尚不能据此访问宿主 Chrome 的既有页面／登录态。

**目标与边界**：首版只接用户选择的标签页，支持查看当前内容、导航与必要的截图／文件交接；选择浏览器或页面不默认开放全部标签页、历史及账户。登录态留在浏览器，不读取 cookie 文件或向模型提供 token。改变页面和执行表单动作沿用具体授权；新 helper／扩展的部署、身份绑定与 OS 权限方式仍需实施设计。

**验收目标**：读取指定标签页并基于真实页面回答；页面关闭、导航、登录失效和用户抢占有明确状态，不能对陈旧页面执行动作；打开链接、填表和最终提交分别核实结果。

<a id="f-051"></a>

### F-051 · ChatGPT 选定历史与附件导入

**需求与依据**：用户反复询问以前交代的资料、旧图片和已经讨论过的方案，希望新助手可沿来源继续。

**当前实现**：没有 ChatGPT 历史导入入口；模型登录 F-002 不授予个人 ChatGPT 聊天记录读取权限。

**目标与边界**：首版以用户主动提供的导出资料或选定对话为输入，保留原消息角色、时间、会话关联与实际可取得的附件。导出格式和附件完整性需先验证；不预设存在通用个人聊天历史 API，不复制桌面应用的私有鉴权或抓取整个账户。导入后召回由 F-010 持有，记忆形成由 F-009 持有；历史内容不自动成为当前指令、真相或长期记忆。

**验收目标**：沿指定旧对话找回资料并指出依据；重复导入去重，分支／编辑／丢失附件明确显示；导入范围可撤销，Forget 后不得由旧索引重新暴露资料。

<a id="f-052"></a>

### F-052 · Codex 选定工程会话导入

**需求与依据**：用户希望复用已有工程讨论、修改约束和交付上下文，避免迁移到 Steward 时重述全部背景。

**当前实现**：没有 Codex 会话来源适配器；桌面应用提供的聊天查看工具不表示 Steward 可调用相同工具。

**目标与边界**：只读用户选择的会话导出或显式允许的本地来源，保留用户要求、助手输出和产物引用的区别。格式属于外部实现细节，初版为实验性适配；不导入凭据，不修改应用状态库，也不把旧工具输出当成当前工作区事实。工程产物只有经现有仓库／Artifact 路径重新授权才可继续操作。

**验收目标**：从选定会话提取原要求及未决事项并附来源；不支持的格式、残缺消息、缺失产物和重复数据可诊断，不能把“曾经报告测试通过”展示为当前已验证。

<a id="f-053"></a>

### F-053 · Pi 选定会话导入

**需求与依据**：用户有把 Pi 中既有家庭设备／工程主题交给另一助手接续的明确委托。它是独立于 Codex 和 ChatGPT 的来源。

**当前实现**：没有 Pi 会话导入入口。

**目标与边界**：首版支持用户选择的会话文件和关联分支，保留角色、先后关系、来源及缺失引用。会话格式的版本兼容在实施前核实，保持实验性；不将 Pi 配置、扩展、自动化、历史审批或认证一并迁移，也不自动执行会话中的命令。

**验收目标**：导入指定主题并从正确分支续读；截断／未知版本／附件缺失明确提示；重复导入、取消、来源移除和 Forget 不造成跨范围召回。

<a id="f-054"></a>

### F-054 · 图片生成与编辑服务

**需求与依据**：用户会委托生成／修改形象、设计品牌素材、迭代参考图片及制作动画，具有明确重复需求。

**当前实现**：F-013 处理视觉输入／OCR，F-012 保存产物；均不表示图片生成服务已接通。

**目标与边界**：首版接一个明确服务完成文生图与参考图编辑，OpenAI Images 为候选，依据[官方图像文档](https://developers.openai.com/api/docs/guides/image-generation)核实实际模型支持。认证、素材上传、费用和产物范围独立于聊天模型连接；保留原图、编辑要求与输出的关联。动画需求单独验证帧、时序和输出支持，不把静态图改扩展名当成 GIF 动画，也不预建多供应商路由。

**验收目标**：生成图片可保存重开，编辑使用确切授权原图；失败、取消、费用上限和未知计费／生成结果可诊断；有动画输出时验证实际播放。服务拒绝或素材缺失不能冒充成功。
