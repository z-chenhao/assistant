# 功能名称：测试方案

新文件应链接功能说明、技术方案和 [主索引](../feature-map.md)。

## 范围与证据

列出需求 ID、入口、配置前提和支持平台。明确软件机制验证、真实服务兼容性与语义效果评测的边界，沿用 [Testing](product.md)。

## 需求场景矩阵

| 需求 ID | 场景与输入 | 可观察结果 / 断言 | 测试层级与入口 | 覆盖缺口 |
| --- | --- | --- | --- | --- |
| 使用真实稳定 ID | 正常或必要失败场景 | 可核实的输出、状态或效果 | 现有测试或待补入口 | 未实现 / 已有覆盖 / 需 Live |

对状态、审批、并发、隐私或重放敏感的功能，增加相应故障与恢复场景；简单功能可直接引用已有测试。

## 测试数据与环境

使用隔离数据根、合成资料和受控 peer；不要复制个人数据库或真实凭据。需要账号或 Guest 平台时，记录真实条件和适用范围。

## 已有入口与执行

链接相关模块测试、系统入口和操作指南。不为本文件重建 runner。计划不是结果：每次执行报告单独保存实际命令、产品版本、环境、通过/失败/跳过/未执行及清理情况。

## 完成判定

关联需求的正常和关键失败路径通过真实目标入口验证，相关文档与状态同步。未覆盖、未知或未运行项如实保留；软件测试不能作为真实模型质量分数。

## 维护

新增或调整需求时同步矩阵；执行报告随运行产生，不覆写历史结果。测试架构的技术取舍记录到功能技术方案的 changelog。
